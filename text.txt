Handoff: LangGraph Agent Backend
Что это
Backend для LangGraph-агента с Human-in-the-Loop: FastAPI + PostgreSQL + JWT-auth + Ollama + SSE-стриминг. Модульная архитектура, готовая к расширению (Redis, Celery, Observability).

Стек: Python 3.12, FastAPI, SQLAlchemy 2.0 (async), asyncpg, Alembic, LangGraph, langgraph-checkpoint-postgres (psycopg v3), ChatOllama (qwen3:4b-instruct), JWT (python-jose), bcrypt, uv.

Окружение: Windows, локальный PostgreSQL (postgresql+asyncpg://postgres:postgres@localhost:5432/agent_db), Ollama на localhost:11434. Запуск через python run.py (не uv run — конфликт с занятыми файлами).

Схема БД (миграции)
Наши таблицы (Alembic):

users — id (UUID), email (unique), hashed_password, is_active, is_superuser, timestamps

approvals — id, user_id FK, run_id FK (nullable, SET NULL), thread_id, interrupt_id, status (pending/approved/rejected), payload (JSONB), comment, decided_at

runs — id, user_id FK, thread_id, status (running/interrupted/completed/failed), input (JSONB), created_at, completed_at

events — id, run_id FK, type (llm_end/tool_end/interrupt/resume/end/error/node_update), payload (JSONB), created_at

LangGraph-таблицы (управляются AsyncPostgresSaver.setup()): checkpoints, checkpoint_blobs, checkpoint_writes, checkpoint_migrations. В миграциях не создаются — в alembic/env.py есть include_object, который их фильтрует.

Важно: Alembic env.py импортирует app.auth.models, app.hitl.models, app.runs.models — иначе autogenerate падает с NoReferencedTableError.

Граф
text
START → llm ─┬─→ approval ─┬─→ tools → llm
             │              └─→ llm (rejected)
             └─→ END
llm_node — ChatOllama с bind_tools([calculator]), системный промпт по-русски

route_after_llm — если tool_calls → approval, иначе END

approval_node — вызывает interrupt({type: tool_approval, tool_calls}). При resume возвращает решение. Если rejected — добавляет ToolMessage("Пользователь отклонил вызов инструмента.") и идёт в llm

tool_node — стандартный ToolNode([calculator])

Checkpointer: AsyncPostgresSaver держится открытым на весь lifespan (context manager). URL конвертируется postgresql+asyncpg:// → postgresql://.

Ключевые механики
HITL flow:

POST /agent/run → создаёт Run (status=running) → runtime.start_run → graph.ainvoke

LLM запрашивает tool_call → approval_node вызывает interrupt() → граф останавливается

Проверяем state.next — если непусто, Run.status=interrupted, создаём Approval через sync_pending_interrupts

POST /approvals/{id}/decide → обновляет Approval → runtime.resume_run(Command(resume={approved, comment}))

Resume: approval_node выполняется заново, interrupt() возвращает значение → переход в tools или llm

Run обновляется до completed/interrupted (если новый interrupt)

SSE stream (POST /agent/stream):

Возвращает StreamingResponse(media_type="text/event-stream")

Отдельная БД-сессия через get_session_factory() (не request-scoped — иначе закроется до конца стрима)

События: run_started → llm_end (пишется в БД, не в SSE) → interrupt → interrupted → completed/error

runtime.stream_run использует graph.astream(stream_mode="updates") с callback on_event для записи в БД

Проверенный функционал
Register → Login → JWT (access + refresh) → /auth/me ✓

POST /agent/run: обычный ответ + tool_call → interrupt ✓

POST /approvals/{id}/decide: approve → tool выполняется; reject → LLM отвечает без tool ✓

Persist: тот же thread_id → граф помнит контекст ✓

GET /runs — список с фильтром по статусу ✓

GET /runs/{id}/events — полный audit log (включая llm_end, которые не идут в SSE) ✓

SSE: run_started → interrupt → interrupted ✓

Известные особенности
Windows event loop: run.py ставит WindowsSelectorEventLoopPolicy до импорта uvicorn. Иначе asyncpg рвёт соединения с WinError 10054.

uv run и запущенный uvicorn: uv пытается синхронизировать venv и падает с os error 5 на занятых файлах. Запускать приложение через python run.py, а не uv run. Если нужно uv run — сначала остановить uvicorn.

PowerShell + curl: использовать Invoke-RestMethod + ConvertTo-Json, либо curl.exe с бэктиками для экранирования. Внутри одинарных кавычек \" не работает.

websockets иногда ломается после неудачных uv run — лечится python -m pip install --force-reinstall websockets.

Ollama qwen3:4b-instruct читерит в reject-сценарии: отвечает «100 * 5 = 500» вместо отказа, хотя инструмент отклонён. Не баг кода — модель. Лечится усилением промпта или большей моделью (отложено).

Что дальше (рекомендация)
Tests — единственное, что уменьшает риск дальнейших изменений. План:

tests/conftest.py: фикстуры test_engine/test_session (отдельная БД agent_test), test_client (httpx AsyncClient), authenticated_client, mock_llm (FakeChatModel с детерминированным tool_call)

tests/unit/: security, auth.service, hitl.service, runs.service, agent.tools

tests/integration/: auth_flow, agent_flow (run→interrupt→approve→completed), agent_reject, stream

Не покрываем: SSE-тайминги (флаки), реальную Ollama (медленно)

Альтернативы (после тестов):

Observability: structured logging (JSON + run_id/thread_id/user_id), OpenTelemetry, Prometheus

SSE refactor: async-итератор вместо callback — чтобы llm_end/tool_end шли в UI

Redis: rate limiting на /auth/login, ревокация refresh

Celery: вынести долгие прогоны из HTTP
